# WhatCanEat

A mobile app that tracks what's in your fridge and suggests recipes you can cook with it. Recipes are generated by AI (Groq), take your allergies and cuisine preferences into account, and can be saved, favourited and logged when you cook them.

The repo is a monorepo with two parts:

| Folder | What it is | Stack |
| ------ | ---------- | ----- |
| `foodapp_backend/` | REST API | Python, FastAPI, Uvicorn, asyncpg, PostgreSQL, Groq, JWT auth (python-jose, bcrypt) |
| `foodapp_frontend/` | Mobile and web app | Expo (React Native), Expo Router, TypeScript, NativeWind (Tailwind) |

## Requirements

- Python 3 with `pip`
- Node.js and `npm`
- A PostgreSQL database (for example Neon)
- A Groq API key
- To run the app: the Expo Go app on a phone, an Android emulator or iOS simulator, or a web browser

## Backend

### 1. Environment variables

Create `foodapp_backend/.env` (it's gitignored and never committed):

```env
DATABASE_URL=postgresql://user:password@host/dbname
GROQ_KEY=your_groq_api_key
SECRET_KEY=any_long_random_string
```

| Variable | Purpose |
| -------- | ------- |
| `DATABASE_URL` | PostgreSQL connection string |
| `GROQ_KEY` | Groq API key used for recipe generation |
| `SECRET_KEY` | Secret used to sign login tokens (JWT, HS256) |

### 2. Install and set up the database

```bash
cd foodapp_backend
python -m venv venv
venv\Scripts\activate        # macOS/Linux: source venv/bin/activate
pip install -r requirements.txt
python -m src.core.database  # creates the tables from src/sql/schema.sql (run once)
```

### 3. Run

```bash
python main.py
```

The API runs on <http://localhost:8000>, and the interactive docs are at <http://localhost:8000/docs>. To check it's working:

- `GET /` returns `{"message": "API is working!"}`
- `GET /health` returns `{"db": "connected"}`

### API overview

| Prefix | Endpoints |
| ------ | --------- |
| `/api/auth` | `POST /register`, `POST /login`, `GET /me` |
| `/api` | `GET/POST /items`, `PUT/DELETE /items/{item_id}`, `GET /ingredients` |
| `/api/ai_food` | `POST /generate-recipe`, `POST /generate-selected-recipes`, `GET /search-recipes`, recipe history, favourites, cookings, `GET /expiration-date/{ingredient_id}` |
| `/api` | `POST /recipes/save/{recipe_id}`, `GET /recipes/saved`, `DELETE /recipes/saved/{recipe_id}` |
| `/api/preferences` | `GET`, `PUT` |

See `/docs` for the full list and request schemas.

## Frontend

```bash
cd foodapp_frontend
npm install
npx expo start
```

Then press `a` for Android, `i` for iOS or `w` for web, or scan the QR code with Expo Go.

**API address:** the app calls the API at the URL set in `API_BASE_URL` in `foodapp_frontend/utils/api.ts`. That is currently the deployed backend on Render. To use your local backend instead, change it to your computer's address (for example `http://192.168.x.x:8000`; a phone can't reach `localhost` on your computer).

